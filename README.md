# 과제 서류 메일 정리 도우미 (시제품)

K-PASS로 받을 수 없는 서류와 K-PASS 마감기(11월 말~연초)에 메일로 들어오는 과제 제출 서류(참여확약서·협약서·재무증빙 등)를
과제 목록에 맞춰 자동 분류하고, **제출현황 엑셀**과 **과제별 폴더(ZIP)** 로 정리합니다.

## 사용 순서
1. **로그인**: 실을 고르고 담당자 이름과 실 비밀번호를 넣습니다. 실마다 접수대장이 따로 저장됩니다. (체험용 실은 비밀번호 없이 가상 데이터로 써볼 수 있습니다.)
2. **과제관리 현황 올리기**: 실에서 쓰는 과제관리 현황 엑셀(.xlsx/.csv)을 그대로 올립니다.
   - 기관별로 한 줄씩인 표와 과제별로 한 줄인 표 모두 읽습니다.
   - 과제번호, 과제명(국·영문), 기관명, 기관 구분, 국가, 책임연구자 이름, 이메일, KIAT 담당자, 연도만 읽습니다.
   - **전화번호 열은 읽지 않고**, 주소·사업자/법인번호 등 쓰지 않는 열도 읽지 않습니다. 셀 안에 섞인 전화번호도 지웁니다(서버에서 한 번 더 확인).
3. **메일 받기**: [수집 메일함에서 새 메일 가져오기](IMAP 연결 시) 또는 두레이에서 저장한 `.eml`·`.zip` 올리기. 이미 접수된 메일은 건너뜁니다.
4. **자동 처리**: 과제·보낸 기관 분류, 서류 종류 분류, 서류 내용 점검(서명·날짜·기관명·과제번호), 재제출 차수·중복 파일 표시, K-PASS 운영 중단 기간이면 '등록 대기' 표시.
5. **메일 접수대장**: 확인 필요·미분류만 골라 과제를 정하고, 서류마다 '이상 없음/보완 필요'를 판정합니다.
6. **기관별 제출현황**: 미제출(D-day 표시)·보완 필요·점검 필요가 도장으로 보입니다. 기관을 골라 **독촉 / 보완 요청 / 접수 확인** 메일을 씁니다.
7. **K-PASS 등록**: K-PASS가 다시 열리면 등록 대기 서류를 모아 받고, 등록 완료로 표시합니다.
8. **과제 기록**: 과제별 타임라인(접수·분류·점검·연락·K-PASS·담당자 변경)과 메모. **담당자 이관**과 **인수인계서**(인쇄·PDF 저장)를 만듭니다.
9. **내보내기**: 엑셀(기관별제출현황·과제별요약·메일목록·첨부파일목록·K-PASS등록·소통이력)과 과제별 폴더 ZIP.

## 서버에 남는 것과 남지 않는 것
| 남는 것 (실별 저장소) | 남지 않는 것 |
|---|---|
| 과제관리 현황 중 필요한 칸 (전화번호 제외) | 메일 본문 원문, 첨부파일 내용 |
| 메일 제목·보낸 사람·날짜·요약, 첨부파일 이름·크기·해시 | 과제관리 현황의 전화번호·주소·사업자번호 등 |
| 분류 결과, 점검 판정, K-PASS 상태, 작업 기록 | |

첨부파일은 브라우저에서만 읽습니다(분류·점검·ZIP). 다른 날 다시 들어오면 기록은 그대로 보이고, 파일이 필요하면 같은 메일을 다시 올리거나 가져오면 원문이 연결됩니다.

## 서류 내용 점검
- 브라우저에서 PDF 글자를 읽어 서명 표시(Signed·Signature·서명·(인) 등), 작성 날짜, 기관명, 과제번호를 찾습니다.
- 참여확약서·협약서는 서명이 없으면 '보완 필요해 보임', 재무증빙은 서명을 필수로 보지 않습니다.
- 스캔본(글자 없음)·PDF가 아닌 파일은 '직접 확인'으로 둡니다. 판정은 항상 담당자가 합니다.

## 서류 제출 대상·기한
[실 설정]에서 서류마다 누가 내는지(참여기관·주관기관·모든 기관·과제 공통)와 제출 기한, K-PASS 운영 중단 기간, 서류 받을 메일 주소, 수집 메일함 폴더를 정합니다.

## 실·권한
- **관리자**(`ADMIN_PASSWORD`): 실을 만들고 실 비밀번호를 정합니다. 서류 내용은 볼 수 없습니다.
- **실 담당자**: 실 비밀번호 + 담당자 이름으로 로그인. 같은 실 기록을 함께 보고, '내 과제만'으로 걸러 봅니다.
- 운영 단계에서는 기관 통합 로그인(SSO)과 인사정보로 실을 자동 지정하는 것을 전제로 합니다.

## 분류 방식
규칙으로 먼저 판단하고, 애매한 메일만 AI(선택)에 넘깁니다.

| 단서 | 점수 |
|---|---|
| 제목·첨부파일명·본문에 과제번호 | 100 / 95 / 90 |
| 발신자가 과제 연락처 (한 과제에만 등록) | 85 |
| 발신 도메인이 해외기관·주관기관 도메인 (한 과제에만 해당) | 55 |
| 기관명 언급 | 35 |
| 과제명 핵심어 절반 이상 일치 | 최대 30 |

- 80점 이상 **자동 분류**, 45~79점 **확인 필요**, 그 미만 **미분류**
- 비슷한 점수의 후보가 둘 이상이면(예: 같은 해외기관이 여러 과제에 참여) 확인 필요로 둡니다
- 과제번호·발신자·도메인 단서 없이 기관명·과제명 언급만 있으면(개인 메일 등) 자동 확정하지 않습니다
- 답장 인용부(이전 메일 내용)에 있는 과제번호는 무시합니다
- 서류 종류는 첨부파일명 키워드로 나눕니다 (`lib/settings.ts`에서 서류 종류·키워드 수정)

## 정리 규칙
```
과제서류정리_YYYYMMDD/
├─ 과제서류정리_YYYYMMDD.xlsx
├─ P0031001_협동로봇 기반 정밀 조립 자동화 기술/
│  ├─ 참여확약서/P0031001_Nordlicht Institute_참여확약서_20261130_원래파일명.pdf
│  ├─ 협약서/...
│  ├─ 재무증빙/...
│  └─ _메일원문/20261130_M001_제목.eml
├─ 01_확인필요/   (검토하지 않은 메일)
└─ 00_미분류/
```

## 정보 보호
- 올린 파일은 **브라우저 안에서만** 처리하며 서버에 저장하지 않습니다.
- 과제관리 현황에서 전화번호 등 필요 없는 정보는 읽지 않습니다.
- 독촉 메일을 보낼 때만 받는 사람 주소와 메일 내용이 발송 서버(SMTP)를 거칩니다.
- AI 판단을 켜면 메일 제목·본문 일부(인용부 제외, 최대 4천 자)·첨부파일 **이름**만 AI로 보냅니다. 첨부파일 내용은 보내지 않습니다.
- AI가 후보에 없는 과제번호나 없는 서류 종류를 답하면 서버에서 버립니다.

## 환경변수
| 환경변수 | 설명 |
|---|---|
| `ANTHROPIC_API_KEY` | 시제품: Claude API 사용 |
| `AI_PROVIDER=internal` + `AI_BASE_URL` + `AI_MODEL` | 기관 내부 이관: 내부 서버의 OpenAI 호환 모델 서버(vLLM·Ollama 등) 사용 |
| `AI_API_KEY` | 내부 모델 서버에 인증이 필요할 때 |
| `UPSTASH_REDIS_REST_URL` `UPSTASH_REDIS_REST_TOKEN` | 실별 접수대장 저장소. **Vercel에서는 필수** (없으면 시연용 메모리) |
| `SESSION_SECRET` | 로그인 세션 서명 |
| `ADMIN_PASSWORD` | 실 관리 화면 |
| `DEMO_DISABLED=1` | 체험용 실 숨기기 |
| `IMAP_HOST` `IMAP_PORT` `IMAP_USER` `IMAP_PASS` | 수집 메일함. 실별 폴더는 [실 설정]에서 지정 |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` | 독촉 메일 발송 (예: 네이버 `smtp.naver.com` / `465` / 앱 비밀번호) |
| `EMAIL_FROM_NAME` `EMAIL_REPLY_TO` | 보내는 사람 이름, 회신 받을 주소 |
| `EMAIL_ALLOWED_RECIPIENTS` | 실제로 보낼 수 있는 받는 주소 (쉼표 구분, `@도메인` 가능, `*`는 기관 승인 후) |

AI를 설정하지 않으면 규칙 기반으로만 동작합니다. AI 제공처는 `lib/ai/provider.ts`, 저장소는 `lib/server/store.ts` 한 파일에서만 바뀝니다.

## 기관 내부 서버 이관
`next.config.mjs`가 단독 실행(standalone) 결과물을 만들므로 그대로 Docker 이미지로 묶을 수 있습니다.

```bash
docker build -t mail-collector .
docker run -p 3000:3000 -e AI_PROVIDER=internal -e AI_BASE_URL=http://내부모델서버:8000/v1 -e AI_MODEL=모델명 mail-collector
```

글꼴도 패키지에 포함되어 있어 인터넷이 없는 내부망에서도 화면이 그대로 보입니다.

## 배포 (Vercel)
저장소를 Vercel에 가져오면 바로 배포됩니다. 환경변수는 `.env.example` 참고 (없어도 규칙 기반으로 동작).
