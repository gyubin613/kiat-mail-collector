# 과제 서류 메일 정리 도우미 (시제품)

K-PASS로 받을 수 없는 서류와 K-PASS 마감기(11월 말~연초)에 메일로 들어오는 과제 제출 서류(참여확약서·협약서·재무증빙 등)를
과제 목록에 맞춰 자동 분류하고, **제출현황 엑셀**과 **과제별 폴더(ZIP)** 로 정리합니다.

## 사용 순서
1. **과제관리 현황 올리기**: 실에서 쓰는 과제관리 현황 엑셀(.xlsx/.csv)을 그대로 올립니다.
   - 기관별로 한 줄씩인 표(과제번호·기관명·기관구분·이메일…)와 과제별로 한 줄인 표(주관기관·참여기관 열) 모두 읽습니다.
   - 과제번호, 과제명(국·영문), 기관명, 기관 구분, 국가, 책임연구자 이름, 이메일, KIAT 담당자, 연도만 읽습니다.
   - **전화번호 열은 읽지 않고**, 주소·사업자/법인번호 등 쓰지 않는 열도 읽지 않습니다. 셀 안에 섞인 전화번호도 지웁니다. 읽지 않은 열은 화면에 표시됩니다.
2. **메일 올리기**: 두레이 메일 필터로 모은 메일을 `.eml`로 저장해 올립니다. 여러 개를 묶은 `.zip`도 됩니다.
3. **검토**: 자동 분류되지 않은 메일(확인 필요·미분류)만 골라 과제와 보낸 기관을 지정합니다.
4. **기관별 제출현황**: 기관마다 내야 할 서류와 접수 여부가 보이고, '미제출 기관만'으로 걸러 볼 수 있습니다.
5. **독촉 메일**: 미제출 기관을 골라 [독촉 메일 쓰기] → 국문(국내)·영문(해외) 초안을 확인·수정 → 시험 발송 → 보내기.
6. **내보내기**: 엑셀(기관별제출현황·과제별요약·메일목록·첨부파일목록·독촉이력)과 과제별 폴더 ZIP을 내려받습니다.

화면의 [가상 데이터로 한 번에 체험하기]를 누르면 가상 과제 30개(기관 66곳), 가상 메일 43통으로 바로 써볼 수 있습니다.

## 서류 제출 대상
서류마다 누가 내야 하는지 화면의 [서류별 제출 대상]에서 정합니다. 기본값은 참여확약서 = 참여기관, 협약서 = 과제 공통(과제당 1부), 재무증빙 = 주관기관입니다.
과제 공통 서류가 빠지면 주관기관 독촉 메일에 함께 넣습니다.

## 독촉 메일 발송
- 초안은 기관별로 만들어지며 요청 서류, 제출 기한, 제출 주소, 파일 이름 규칙이 들어갑니다. 두 번째부터는 '재안내'로 표시됩니다.
- **실제 발송은 허용 목록(`EMAIL_ALLOWED_RECIPIENTS`)에 있는 주소로만** 됩니다. 목록에 없는 주소는 서버에서 막고 화면에 사유를 보여줍니다.
- [나에게 시험 발송]은 받는 사람 대신 입력한 내 주소로 보내며 제목에 '[시험 발송]'이 붙습니다.
- 발송 설정이 없으면 [메일 프로그램으로 열기]와 [복사]로 보낼 수 있습니다.
- 발송 이력은 이 브라우저에 남고(기관별 독촉 횟수·마지막 날짜), 엑셀 '독촉이력' 시트로 내보낼 수 있습니다.

## 분류 방식
규칙으로 먼저 판단하고, 애매한 메일만 AI(선택)에 넘깁니다.

| 단서 | 점수 |
|---|---|
| 제목·첨부파일명·본문에 과제번호 | 100 / 95 / 90 |
| 발신자가 과제 연락처 (한 과제에만 등록) | 85 |
| 발신 도메인이 해외기관·주관기관 도메인 (한 과제에만 해당) | 55 |
| 기관명 언급 | 35 |
| 과제명 핵심어 절반 이상 일치 | 최대 30 |

- 80점 이상 **자동 분류**, 45~79점 **확인 필요**, 그 미만 **미분류**
- 비슷한 점수의 후보가 둘 이상이면(예: 같은 해외기관이 여러 과제에 참여) 확인 필요로 둡니다
- 과제번호·발신자·도메인 단서 없이 기관명·과제명 언급만 있으면(개인 메일 등) 자동 확정하지 않습니다
- 답장 인용부(이전 메일 내용)에 있는 과제번호는 무시합니다
- 서류 종류는 첨부파일명 키워드로 나눕니다 (`lib/settings.ts`에서 서류 종류·키워드 수정)

## 정리 규칙
```
과제서류정리_YYYYMMDD/
├─ 과제서류정리_YYYYMMDD.xlsx
├─ P0031001_협동로봇 기반 정밀 조립 자동화 기술/
│  ├─ 참여확약서/P0031001_Nordlicht Institute_참여확약서_20261130_원래파일명.pdf
│  ├─ 협약서/...
│  ├─ 재무증빙/...
│  └─ _메일원문/20261130_M001_제목.eml
├─ 01_확인필요/   (검토하지 않은 메일)
└─ 00_미분류/
```

## 정보 보호
- 올린 파일은 **브라우저 안에서만** 처리하며 서버에 저장하지 않습니다.
- 과제관리 현황에서 전화번호 등 필요 없는 정보는 읽지 않습니다.
- 독촉 메일을 보낼 때만 받는 사람 주소와 메일 내용이 발송 서버(SMTP)를 거칩니다.
- AI 판단을 켜면 메일 제목·본문 일부(인용부 제외, 최대 4천 자)·첨부파일 **이름**만 AI로 보냅니다. 첨부파일 내용은 보내지 않습니다.
- AI가 후보에 없는 과제번호나 없는 서류 종류를 답하면 서버에서 버립니다.

## 환경변수 (모두 선택)
| 환경변수 | 설명 |
|---|---|
| `ANTHROPIC_API_KEY` | 시제품: Claude API 사용 |
| `AI_PROVIDER=internal` + `AI_BASE_URL` + `AI_MODEL` | 기관 내부 이관: 내부 서버의 OpenAI 호환 모델 서버(vLLM·Ollama 등) 사용 |
| `AI_API_KEY` | 내부 모델 서버에 인증이 필요할 때 |
| `APP_PASSWORD` | 설정 시 AI 호출·메일 발송에 접속 비밀번호 필요 (외부 배포 시 권장) |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` | 독촉 메일 발송 (예: 네이버 `smtp.naver.com` / `465` / 앱 비밀번호) |
| `EMAIL_FROM_NAME` `EMAIL_REPLY_TO` | 보내는 사람 이름, 회신 받을 주소 |
| `EMAIL_ALLOWED_RECIPIENTS` | 실제로 보낼 수 있는 받는 주소 (쉼표 구분, `@도메인` 가능, `*`는 기관 승인 후) |

AI를 설정하지 않으면 규칙 기반으로만 동작합니다. AI 제공처는 `lib/ai/provider.ts` 한 파일에서만 바뀝니다.

## 기관 내부 서버 이관
`next.config.mjs`가 단독 실행(standalone) 결과물을 만들므로 그대로 Docker 이미지로 묶을 수 있습니다.

```bash
docker build -t mail-collector .
docker run -p 3000:3000 -e AI_PROVIDER=internal -e AI_BASE_URL=http://내부모델서버:8000/v1 -e AI_MODEL=모델명 mail-collector
```

글꼴도 패키지에 포함되어 있어 인터넷이 없는 내부망에서도 화면이 그대로 보입니다.

## 배포 (Vercel)
저장소를 Vercel에 가져오면 바로 배포됩니다. 환경변수는 `.env.example` 참고 (없어도 규칙 기반으로 동작).
